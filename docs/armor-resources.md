# 盔甲样式资源说明

适用：v0.5.0。资源格式沿用 S02，衣柜采用四部位入口与正面样片网格。

## 在衣柜中选择盔甲外观

通过原有盔甲架入口打开衣柜，进入第三个“盔甲”页签。这里修改的是外观，不会生成或取下真实盔甲；空槽仍为空，真实装备的属性、耐久、饰纹和附魔不变。

- 先点击上方“部位”入口，选择头盔、胸甲、护腿或靴子。入口始终显示当前编辑部位，面板列出各槽当前草稿。
- 再选“原版”“隐藏”或网格中的自定义纹理，只改变该槽。切换部位保留其他草稿和各槽页码。
- 每页 4×2 资源格显示当前部位的正面纹理样片与简短名称；左侧 3D Preview 展示完整装备效果。透明样片不补皮肤；没有真实装备也能查看二维资源。
- 样式按 ID 稳定排序，只有支持当前槽的资源列出。滚轮或箭头每次翻一页；选中格有明确边缘与蓝色细线。底部显示当前选择，悬停查看完整名称、ID、支持槽、来源和纹理状态。
- 纹理正在下载时，已知合法样式可以选择，预览暂用原版；资源就绪后自动更新，无需重开或重复应用。服务器目录尚在同步与可信空列表是不同状态。
- 已保存但失效的样式保留原 ID，暂时按原版显示。不要为“修复列表”重新应用；管理员恢复样式并重载后会自动恢复。你仍可明确清为原版／隐藏或选择合法的新样式。

Cape、Outfit 与 Armor 共享一份草稿。切换页签不会保存；确认三类预览后点击一次“应用”。等待服务器确认期间可以浏览，但不能更改草稿。成功后衣柜保持打开，无新修改时应用禁用。取消、E 或 ESC 丢弃全部未应用修改，不只丢弃当前页。

发生外部字段冲突时，先核对提示；“重新加载”丢弃三类全部未提交草稿并采用最新服务器状态。存在未确认请求时不可重新加载，也不会自动重试。

顶部进入盔甲／装束页自动朝向正面，进入披风页朝向背面；之后可以自由拖动。CAPE／ELYTRA 预览模式与窗口缩放不会重置手动朝向。Tab／Shift+Tab 浏览控件，Enter／Space 激活焦点控件；完整槽值和资源说明也提供给旁白，但人工可听性以本次验收记录为准。

## 安装位置与文件

资源放在服务器（或单人集成服务器）的 `config/3790s-fashion/armor/`。正常连接的玩家通过正式资产协议下载，不必在客户端手工安装同一份 PNG。

```text
armor/
  blue/
    armor.json
    outer.png
    inner.png
```

```json
{
  "format_version": 1,
  "id": "blue",
  "name": "蓝色 UV 标记",
  "slots": ["head", "chest", "legs", "feet"],
  "textures": {"outer": "outer.png", "inner": "inner.png"}
}
```

ID 必须与目录名相同，长度 1～32，首字符为小写字母或数字，后续可用小写字母、数字、下划线、点、连字符。显示名不参与保存身份；最多 80 个 Unicode 字符、240 个 UTF-8 字节，不允许空白名称或控制字符。禁止重复键、未知字段和隐式类型转换。

只支持头盔的样式可以只声明 `slots: ["head"]` 和 `textures: {"outer": "outer.png"}`。缺少未声明的部位不会导致样式失效；声明 `legs` 却没有 inner 会拒绝整份样式。样式不能包含未声明的额外文件。

## PNG 与 UV

outer 和 inner 均为 **64×32、8 位 RGBA、非交错 PNG**。Alpha 只允许 0 或 255，不能使用半透明、索引色、灰度或 RGB-only 文件。单 PNG 最多 16,384 字节。按像素绘制，不进行插值放大；游戏使用原版盔甲模型与最近邻纹理采样。

| 文件 | 消费槽位 | 原版几何 |
| --- | --- | --- |
| outer | HEAD、CHEST、FEET | HUMANOID |
| inner | LEGS | HUMANOID_LEGGINGS |

两张纹理使用原版 64×32 盔甲 UV 布局；并非 Outfit 的 64×64 皮肤布局。头部 UV 位于左上区域，身体在下排中部，双臂使用下排右侧区域，腿部使用下排左侧区域。可用不同颜色标记各 UV 面，先在衣柜的二维样片与三维预览中核对方向，再应用。

HEAD/CHEST/FEET 可引用同一份 outer；LEGS 使用 inner。系统不改变模型几何，也不处理自定义 3D 模型。纹理文件名限小写字母或数字开头，随后小写字母、数字、下划线或连字符，总干名最多 44 字符，后缀 `.png`。不接受子目录、绝对路径、URL、符号链接或特殊文件。

## 显示语义

- ORIGINAL：完整使用原版盔甲效果。
- HIDDEN：隐藏对应槽的整个盔甲视觉，包括基础层、染色、饰纹、附魔和相应轮廓。
- CUSTOM：仅在该槽真实存在可渲染盔甲时替换基础纹理；保存选择不绑定某个 ItemStack，空槽不会生成盔甲。

标准单基础层盔甲及皮革受支持。皮革仍按真实物品染色，覆盖层仍使用原版纹理；饰纹和附魔沿用真实装备的原版实现。基础 PNG 透明不会取消独立覆盖层或饰纹；需要完整隐藏应使用 HIDDEN。不支持的多层结构整槽回退原版，并有限度记录原因。

CUSTOM 不改变真实物品、数量、组件、耐久、附魔、属性或伤害，也不替换物品栏图标。Cape、Outfit、头颅物品与 Elytra 属于其他渲染路径。

## 重载、缺失与恢复

管理员使用现有 `/fashion3790 reload` 共同重载 Outfit 和 Armor；本命令不扩展为 Cape 热重载。应先完成文件编辑，再执行命令，扫描期间不修改目录。

相同 ID 的 PNG 内容变化会产生新的内容 hash。在线玩家自动下载并使用新纹理，无需重连或重新 Apply；纯内容变化不改变玩家选择 revision。

资源缺失、不支持对应槽、或单个样式校验失败时，已保存 CUSTOM **保留**，服务端有效外观回退 ORIGINAL，属于 dormant。恢复合法资源并重载后自动恢复。尚未就绪或客户端解码失败也只影响本地显示，不自动清除保存选择。新增缺失／不适用的 CUSTOM 会被拒绝；不变 dormant 不阻碍 Cape/Outfit 的无关编辑。

单个坏样式会隔离；整个根不可读、总预算超限或检测到候选读取变化时，整次重载失败并保留此前有效快照。无自动删除 Armor 保存引用的机制。

## 限额与排障

最多 128 styles、256 个不同 PNG；每 style 最多一份 4,096 字节 metadata 和两张 PNG。有效快照总量最多 4 MiB，根扫描条目最多 4,096。拒绝损坏、截断、CRC 错误、尺寸错误、非法 Alpha 和 hash 不匹配。下载预算按连接累计，不因重复重载无限重置。

排障时先看服务器样式隔离／重载失败信息，核对文件名、字段、槽声明与 PNG 模式。客户端只按当前服务器 Registry 授权的内容 hash 获取资源，不接受任意本机路径或 URL。扫描使用受控的读取前后身份和内容复核，不承诺抵御管理员并发恶意替换目录的原子隔离。
