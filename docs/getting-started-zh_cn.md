# 3790's Fashion 入门（1.0 候选）

本文适用于 `1.0.0`，不是正式 1.0 发布声明。当前已发布版本仍为 0.5.0；本地候选安装包尚未发布。[English](getting-started-en_us.md)

## 安装与打开

使用 Minecraft Java 26.2、Java 25、Fabric Loader 0.19.3 和 Fabric API 0.158.0+26.2。将本阶段主 JAR 和 Fabric API 放入实例的 `mods/`；多人完整功能需要服务器及客户端都安装，单人只装客户端。升级前正常退出并备份配置和世界，不要同时放入两个主 Mod 版本。

玩家不需要 Visual API 编译接口 JAR，也不需要 Elytra Slot 附属。开发接口是编译输入，不能放入玩家 `mods/`。

找到原版盔甲架，拿木棍等不会触发该架原版动作的物品右键。放上／取下装备优先；没有原版动作时打开衣柜。按住次要使用（通常为潜行）可绕过衣柜。不会增加新物品或改变装备属性。

## 选择、预览和保存

- **披风 Cape**：选择原版或资源。绑定的 Elytra 外观随 Cape 选择；没有单独的隐藏披风／Elytra 选择。
- **装束 Outfit**：先选全部、分组或详细部位，再选原版、无外层或资源。无外层只隐藏原版皮肤外层，基础人物仍在；部分资源只改变其支持部位，其他部位保留。
- **盔甲 Armor**：先选头盔、胸甲、护腿或靴子，再选原版、隐藏或资源。隐藏完整盔甲视觉，但实际物品、属性和耐久不变；没有真实盔甲时不会生成装备。

右侧二维样片用来浏览资源，不包含实际皮肤、染色、饰纹或附魔；左侧三维预览反映玩家与真实装备。预览按钮图标表示当前 Cape／Elytra 状态，提示说明点击后的状态。进入 Cape 页朝背面，Outfit／Armor 朝正面，之后可拖动；预览模式切换不会改变保存选择。

三页共享一份草稿。切页／部位不会保存或丢失草稿；点一次**应用**提交全部修改。服务器成功确认后留在原窗口，无变化时应用禁用。取消、E、ESC 丢弃尚未提交的草稿，不能撤回已经发出的请求或成功提交。重开检查保存结果。

外部修改冲突时先读提示；衣柜的**重新加载**丢弃所有草稿并采用最新保存选择，等待确认期间不可用。它与管理员资源重载不同。Tab／Shift+Tab 移动焦点，Enter／Space 激活；长提示按 PageUp／PageDown 翻阅完整名称和原因。语言跟随原版设置；先关衣柜再改语言会按正常规则丢弃未提交草稿。

## 资源放在哪里

单人使用**当前游戏实例根目录**的 `config/3790s-fashion/`，不是世界的 config；Dedicated 使用**服务器运行根目录**下同一路径。多人资源由服务器提供，玩家不必逐张安装。以下 `<id>` 是目录名和保存身份，不是显示名称。

| 资源 | 目录与文件 | 基本约束 | 生效方式 |
| --- | --- | --- | --- |
| Cape | `capes/<id>/cape.png`；或另加 `elytra.png`；或只用 `cape_elytra.png` | 64×32 PNG，每张 ≤65536 字节；三种布局不可混用 | 正常重启服务器／单人世界 |
| Outfit | `outfits/<id>/wide.png` 和／或 `slim.png` | 64×64 PNG，每张 ≤65536 字节；不自动转换臂宽 | `/fashion3790 reload` |
| Armor | `armor/<id>/armor.json` 和声明的 PNG | 必须有 JSON；64×32、8 位 RGBA、非交错、Alpha 0/255，每张 ≤16384 字节 | `/fashion3790 reload` |

Cape 可从安装包的 `templates/capes/` 复制现有样例；[三种 Cape 布局](cape-cosmetic-asset-layout.md)。Outfit PNG-only 从外层 UV 非透明像素推断部位；同时提供 wide/slim 时推断部位必须相同。显式 JSON 可以声明全透明部位；有错误 JSON 时不会偷偷退回 PNG-only。

以下是 **outfit.json 示意片段**，不是独立可安装资源；还需自备符合 WIDE UV 的 `wide.png`：

```json
{"schema_version":1,"parts":["head"],"models":["wide"]}
```

以下是目录 `demo_helmet` 的 **armor.json 示意片段**，还需自备符合盔甲 UV 的 `outer.png`：

```json
{"format_version":1,"id":"demo_helmet","name":"示例头盔","slots":["head"],"textures":{"outer":"outer.png"}}
```

护腿使用 inner，其他三槽用 outer。完整字段、文件名、UV、大小与安全限制见[盔甲资源说明](armor-resources.md)。本说明不附赠 Outfit／Armor 图片或自动安装资源。

## 更新、缺失与排障

管理员完成所有文件编辑后执行 `/fashion3790 reload`，共同重扫 Outfit＋Armor；扫描期间不要修改目录。当前客户端自动更新资源和预览，无需重复 Apply。Cape 不支持此热重载，也没有自动文件监听。无命令权限时请联系服主。

| 情况 | 选择与显示 |
| --- | --- |
| 列表同步中、下载中 | 等待完成；不是可信空列表，不必反复 Apply |
| 目录仍存在但内容暂时无效 | 已保存引用保留，显示安全回退；修好后按对应方式重载／重启 |
| 明确可信删除 Cape／Outfit 目录 | 服务器在扫描／协调时清除对应保存引用；Outfit 只影响引用该 ID 的部位 |
| Armor 缺失、删除或槽不再支持 | 保存 ID 保留并暂用原版；恢复合法资源后自动恢复 |
| 整个根不可读或扫描不可信 | 保留此前可信快照；先查服务器错误，不以空列表覆盖选择 |

玩家保存位于当前世界 `data/fashion_3790/player_fashion.dat`；schema 4 由服务器维护，不手工编辑。客户端下载缓存位于游戏实例 `3790s-fashion/cache/`，不是服主资源目录，也不是保存文件。排障应先核对服务器资源及日志，不删除存档来修复贴图。

升级会按现有规则读取旧 schema 与旧身份位置；降级需要恢复升级前备份。固定 Elytra Slot v1 的世界支持保持，但附属 BODY 在原版物品栏的翼／披风一致性仍有限制，真实 BODY 组合预览后置。主动 Cape／Elytra 试穿与真实胸槽翼不因此取消。1.0 不承诺任意第三方 Mod 兼容。
